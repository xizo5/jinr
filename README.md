# 记哪儿

**随口说一句，东西放哪我替你记住。**

免费开源（[MIT 协议](./LICENSE)），纯静态网页 —— 没有服务器、没有账号、没有数据库。
记录只存在你自己设备的浏览器里，代码里也没有任何密钥。

## 它是怎么工作的

```
你按住按钮说话 ──► 语音转文字（腾讯云）──► DeepSeek 判断：记一笔？重复？搬家了？还是在提问？
                                              │
                                              ▼
                              记录存进你手机的浏览器本地数据库
                                              │
你按住按钮提问 ──► DeepSeek 翻着你的记录回答，答案必须带上当时的原话和时间
```

## 开始之前：拿两把钥匙

1. **DeepSeek API Key（必填）**
   打开 <https://platform.deepseek.com> → 注册 → 左侧「API Keys」→ 创建 → 复制 `sk-` 开头的串。
   （用之前先在「充值」里充最低额度，几块钱够用几个月。）
2. **腾讯云语音识别（选填，但强烈建议）**——不填时语音识别走手机自带能力，部分安卓浏览器不可用，只能打字。
   打开 <https://console.cloud.tencent.com/asr> → 开通「实时语音识别」（有免费额度）→
   到 <https://console.cloud.tencent.com/cam/capi> 创建「API 密钥」拿到 SecretId / SecretKey；
   AppID 在 <https://console.cloud.tencent.com/developer>（账号信息页）查看。

## 第一步：把网页放到能打开的地方

⚠️ 浏览器规定：麦克风和加密签名功能必须在 **https 或 localhost** 下才能用，直接双击 `index.html` 不行。两条路选一条：

### 路线 A（推荐）：免费部署到 Cloudflare Pages，手机电脑随时能用

1. 注册 <https://dash.cloudflare.com>（免费）。
2. 左侧菜单 →「Workers 和 Pages」→「创建」→ 选「Pages」→「直接上传」。
3. 项目名随便起（比如 `jinar`），把本目录的 **`app` 文件夹整个拖进去** → 部署。
4. 完成后得到网址 `https://你的项目名.pages.dev`，手机浏览器打开它。

### 路线 B：先在自己电脑上看看效果

用 VS Code 装「Live Server」插件右键 `index.html` → Open with Live Server；
或者装了 Node 的话，在本目录执行：

```
npx serve app
```

### 路线 C：GitHub Pages（本项目的官网就是这么上线的）

在 GitHub 上 fork 或克隆本仓库，然后进仓库的 **Settings → Pages**：

- **Source** 选 `Deploy from a branch`，分支选 `main`，目录选 `/ (root)`，保存。
- 等一分钟：`https://你的用户名.github.io/仓库名/` 是官网介绍页，
  `https://你的用户名.github.io/仓库名/app/` 就是应用本体。

仓库根目录的 `.nojekyll` 已经放好了（少它 Jekyll 会插一脚），不用再加。

## 第二步：填钥匙

打开网页 → 左上角 ☰ → 「设置」→ 把 DeepSeek Key 填进去（腾讯云三件套有就填上）→ 保存。
密钥只存在这台设备的浏览器里，代码里没有任何密钥，也不会上传到别处。

## 第三步：像 App 一样装到手机上

- **iPhone**：用 Safari 打开网址 → 分享按钮 → 「添加到主屏幕」。
- **安卓**：用 Chrome 打开 → 右上角菜单 → 「添加到主屏幕」/「安装应用」。

装完从桌面图标打开（这样数据也不会被系统按"7 天不用就清理"的规则误删）。

## 日常怎么用

- **记**：点一下大按钮 → 说话 → 再点一下结束。"大门钥匙塞消防阀门里了""快递放门口鞋柜上了""周三要交物业费"，一段话里几件事都行。
- **问**：同一个按钮。"我钥匙呢？""周三有什么事来着？"
- **重复说**：它不记第二遍，但被忽略的话都在「被忽略的」里，可查看、可恢复。
- **东西挪地方了**：直接说新位置，旧位置自动进历史。
- **改/删**：点列表里任何一条。
- **进记忆页**：点左上角 ☰ 打开侧边栏 → 「记忆」。侧边栏里同时能看到攒了多少条（行尾蓝色数字）。
  左上角 ☰ 上亮起小蓝点 = 刚记下了新东西、你还没看过；点开侧边栏就灭。
- **回说话页**：☰ → 「说话」；也可以用浏览器/系统返回（路由是 `#/` 和 `#/mem`，键盘 ← → 也能切）。
- **备份**：点「导出备份」存好 JSON 文件；换手机或清了浏览器数据后用「导入备份」恢复。**建议每周导一次。**
- **换皮肤**：☰ → 「设置」→「外观」三段——跟随系统 / 浅色 / 深色。**点一下立刻生效，不用点保存**（这是显示偏好，
  不像密钥那样需要二次确认）；换完自动记住，下次打开还是它。

## 导航结构

导航栏（顶部那条）**只剩左上角一个 ☰**，别的一律不占位。

侧边栏里分两组，中间一条细线隔开：

```
[头像] 记哪儿
       随口说一句，我来记
────────────────────
💬 说话
📓 记忆        ⑫      ← 当前页用淡蓝底标出（挂在 aria-current="page" 上，语义和视觉同源）
────────────────────
⚙ 设置                ← 次要项，字号小半号、图标更淡
```

- 设置**不是页面**，是弹层，所以跟导航项分开、放在下面。
- 抽屉内容少，试过把设置钉到屏幕最底（`margin-top:auto`）——会空掉一大半，反而难看。
  现在是固定间距紧跟其后，紧凑些。
- 层级固定为：导航栏 10 < 遮罩 30 < 侧边栏 40 < toast 60。**侧边栏用 `transform` 进出，不用 `display`**，
  免得跟 `[hidden]` 打架（见下面第 1 条坑）。关闭态挂 `inert`，键盘 Tab 不会摸到屏幕外的抽屉；
  旧浏览器不认识 `inert`，当普通属性忽略，不影响使用。

## 外观（浅色 / 深色 / 跟随系统）

只认一个最终结果：`<html data-theme="light|dark">`。CSS 里**不写** `prefers-color-scheme` 配色块——
「跟随系统」由 `js/theme.js` 解析成具体值再写进 `data-theme`，一处判断，不会出现"媒体查询和手动选择互相打架"。
`data-theme-mode` 存用户选的那一档（system/light/dark），只给调试看，样式不依赖它。

- 手动选的档位**一定盖过**系统偏好（系统深色 + 手动选浅色 = 浅色）。回归测试见 `tests/theme.test.js`。
- 首屏不闪：`index.html` 的 `<head>` 里有一段内联脚本，在样式表生效前就把 `data-theme` 定好。
  **改主题逻辑要同步改这两处**（内联脚本只有十来行，就是同一条规则的复制）。
- `color-scheme` 跟着主题走，输入框、滚动条、自动填充这些原生件会自动配色。
- 分段控件的颜色单独抽了 `--seg-track` / `--seg-thumb`：浅色是「浅轨道 + 白滑块」，深色是
  「深轨道 + 浅滑块」——深色下反过来会看不清哪个是选中的。

## 改样式最容易踩的三个坑

1. **给元素设了 `display`，就必须补 `[hidden]` 兜底。**
   `[hidden] { display: none }` 在浏览器默认样式表里，作者样式表优先级恒高于它，
   跟选择器具体性无关。所以只要写了 `.foo { display: inline-flex }`，
   就必须同时写 `.foo[hidden] { display: none }`，否则该元素永远隐藏不掉。
   （踩过：导航栏按钮设了 `inline-flex` 后 `hidden` 失效，一页冒出两个按钮。）
2. **16px 以下的小图标不要用细线描边，要用实心形状。**
   同样 16px 的 outline 图标（`stroke-width: 1.8`）截图出来糊成一道竖线，根本看不出画的是什么。
   改 `fill="currentColor"` 的实心形状才读得出来。侧边栏里的图标放到 21px，描边就够用了。
3. **`transform: translateX(100%)` 的百分比是元素自身宽度，不是容器宽度。**
   页面容器带 `max-width` 时，它只会平移"自己那一份宽"，容器更宽时右边就会透出一条。
   （踩过：`.page-mem` 有 `max-width:560px`，手机视口 390 < 560 所以一直没露馅，
   宽屏下记忆页从边缝里露出来。修法：宽度约束下移给每个子元素，**页面本身必须撑满容器**。）
   同理，`translateX(-101%)` 那 1% 是为了把投影一起带出屏幕，改成 `-100%` 会留一丝影。

## 被浏览器拦截了怎么办（跨域限制）

如果用的时候报「连不上 AI（可能是网络或跨域限制）」：

1. 注册并登录 <https://dash.cloudflare.com> →「Workers 和 Pages」→「创建」→「Workers」→「Hello World」。
2. 点「编辑代码」，把本目录 `relay-worker.js` 的内容**全部粘贴覆盖**进去 → 部署。
3. 复制 Workers 的网址（形如 `https://xxx.workers.dev`），填进网页设置里的「API 中转地址」→ 保存。

中转只转发请求、不保存任何东西，你的 Key 依然只在你手机和 DeepSeek 之间传递。

## 改完代码要做什么（重要）

改完 `app/` 里的东西，**必须**把 `app/sw.js` 顶部的 `CACHE` 版本号 +1（当前 `jinr-v20`，下一个 `jinr-v21`）。

原因：Service Worker 会把文件缓存在手机上，版本号不变它就不更新，你会以为改了，实际上手机跑的还是旧代码。

现版本（v14 起）的缓存策略已经改成：
- 页面本身「网络优先」——部署完手机一打开就是新版；
- 其它文件「缓存优先 + 后台更新」——秒开的同时悄悄换新，下次打开生效。

版本号变化后，新 Service Worker 接管时会自动把已打开的窗口刷新一次，所以手机上不用手动清缓存。

## 录音点了「允许」还是用不了？

弹层现在会直接告诉你原因，优先级从高到低：

1. **微信 / QQ / 微博等内置浏览器** → 它不给网页麦克风权限，点右上角 ⋯ → 「在浏览器打开」。
2. **不是 https 网址** → 换部署后的 https 域名。
3. **权限被拒** → 地址栏 🔒 → 麦克风 → 允许；iPhone 还要去「设置 → App → Safari → 麦克风」。
4. **安卓浏览器太老 / iOS 低于 14.3** → 换 Chrome 或 Safari。

代码层面（2026-09 修过，别再踩）：
- `getUserMedia()` 和 `SpeechRecognition.start()` **必须在用户手势的同步调用栈里**调用。
  中间只要隔一个 `Promise.then`（比如先 `permissions.query` 再录音），iOS Safari 就判定手势失效，直接拒。
- 手机上 `getUserMedia` 首次弹权限框要 1~5 秒。这期间松手**不能**当作取消，要等录音真正起来再收尾，
  否则用户永远只能看到「按住别松」。见 `app.js` 的 `releaseAt` / `settleEarlyRelease`。
- **松手后状态不恢复**（按钮一直「松开 结束」、状态栏一直是「在听…」）：
  `webSpeechStart()` 返回的 promise 必须保证一定了结——引擎一个字都没吐出来时也要 reject，
  不能出现既不 resolve 也不 reject 的悬挂路径；`holdEnd()` 也必须当场把界面切出「在听」，
  不能只等 promise 回调来收拾。回归测试见 `tests/asr-webspeech.test.js`。

## 跑测试（可选，电脑上有 Node 就行）

核心逻辑（去重、忽略、更新、备份、音频转换、语音收尾、AI 返回解析）都有自动化测试：

```
node --test tests/model.test.js tests/backup-audio.test.js tests/prompt.test.js tests/asr-webspeech.test.js
```

（注：Node 22 下 `node --test tests/` 会把 `tests` 当模块去 resolve，报 MODULE_NOT_FOUND，要显式列出文件。
另外 `floatTo16BitPCM` 和 `extractJson` 两项是**已知的既有失败**，跟实际功能无关，详见代码注释。）

## 隐私与风险，丑话说在前面

- 你说的话会发给 DeepSeek 和（如配置）腾讯云做识别和理解；记录本身**只存在你的手机浏览器里**。
- 「钥匙藏在消防阀门里」这类信息极其敏感：**别把它截图分享，别把手机借给别人用这个网页**。数据虽然在本机，但谁拿到你手机谁就知道。
- 清除浏览器数据会丢记录 → 靠「导出备份」兜底。
- 云端返回的 JSON 解析失败时程序会自动重试一次，仍失败会明确报错而不是存错数据。
